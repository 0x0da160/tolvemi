# 速度の基準（v1.0.0）

v1.0.0 の速度の基準は、いまの計測値を基準として記録し、後の変更がその**二倍を超えたら検出する**ことにします（2026-10-13 の決定）。絶対の時間の目標は置きません。設計書（[LPTL 設計方針 v1](../spec/lptl-v1/LPTL_design_v1.md) の G2）は、実用の閾値を対象環境と実測から決め、恣意的な性能目標を置かないよう求めています。この基準はその求めに合わせたものです。

資源上限（既定の steps 10^7、割り当て 10^6）は、言語の契約として別に残ります。この文書の基準は、後の変更を見張るための値です。v1.0.0 では、この手順と判定の規則を凍結します。

## 測るもの

| 名前 | 内容 |
|---|---|
| W1 | `eval/tasks` の参照プログラム 99 問を、各 `hidden.json` のケース（計 2970 件）で実行する。入力は小さい。 |
| W2 | 総和（`sum_all`）、二乗の和（`square_filter_sum`）、並べ替え（`sort_max`）を、100・300・1000・1万・10万要素で実行する。入力は決まった式で作る。 |

- 時間は一回のプロセスの壁時計時間（検査・復号・実行・符号化を含む）。各ケース 5 回の中央値。
- 論理量は `run --stats` の steps と allocated_nodes。決定的なので、5 回の実行で一致することを確かめる。
- 出力は、W1 が `hidden.json` の期待値と、W2 が Python で計算した値と照合する。

## 実行

リポジトリの根から実行します。

```sh
python3 bench/speed_baseline.py record bench/baseline.json   # 基準を書く（意図した変更のときだけ）
python3 bench/speed_baseline.py check bench/baseline.json    # 基準と比べる（退行があれば終了コード 1）
```

`TLVM_BIN` で処理系を、`REPEATS` で各ケースの回数を変えられます（既定は 5）。`check` は数分かかります。

## 判定の規則

- **論理量**（steps、allocated_nodes）：どのケースも基準の二倍を超えたら退行。決定的なので、どの機械でも比べられます。
- **完了の仕方**：基準で完了していたケースが上限で止まるようになったら退行。
- **時間**：cpu と nproc が基準と同じ機械のときだけ比べます。W1 の合計が二倍を超えたら退行。基準の中央値が 20 ms 以上のケースは、それぞれ二倍を超えたら退行（20 ms 未満は起動の揺れが大きいので比べない）。上限で止まったケースは時間を比べません。
- **失敗**：出力が期待値と違う、5 回の論理量が一致しない、基準にないケースがある、基準のケースが欠けている。

## 基準の値

記録：`bench/baseline.json`。コードは 5f72195 と同じ木です（main の b0539e6 は PR #27 のマージ）。Intel Xeon 2.80 GHz・4 コア、rustc 1.97.0、Python 3.13.16、各ケース 5 回の中央値。

- 最小の入力の一回の実行（起動と検査を含む、20 回の中央値）：3.4 ms。
- W1（2970 件）：合計 14.9 s、中央値 4.29 ms、90% が 6.67 ms 以下、最大 110.6 ms（`99-bst_height` の h12）。全件で出力が期待値と一致しました。steps の最大は 3,955,823、割り当ての最大は 479,376（どちらも `99-bst_height` の h10）で、既定の上限には届きません。

## 所見

- **並べ替え（`sort_by`）の割り当ては要素数の二乗で増えます。** 100 要素で 20,501、300 要素で 181,501 で、どちらも 2n²+5n+1 に一致します（式は二点からの推定）。既定の割り当て上限（100 万）には約 700 要素で届き、1000 要素は上限で止まります。これは時間ではなく論理量の問題です。直すかどうかは別に判断します。
- 大きい入力では、時間は要素数にほぼ比例します（総和は 1 万要素で約 0.1 秒、10 万要素で約 1.0 秒）。
- W1 の参照プログラムの steps は、既定の上限（1000 万）の約 40% までです。

## 制限

- 時間の基準はこの機械の値です。機械が変わると時間は比べられません（論理量は比べられます）。別の機械で使うときは、その機械で `record` し直します。
- 時間は実行ごとに数%から十数%揺れます（W1 の合計は、別々の記録で 15.6 秒と 14.9 秒）。二倍の規則はこの揺れより十分大きい値です。
- 基準を書き直すのは、意図した変更のときだけです。差分は PR で説明します。
