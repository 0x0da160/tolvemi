# Tolvemi：名称・表記・設計思想

- 正式名称：**Tolvemi**
- 日本語の読み：**トルベミ**
- 公式省略表記：**tlvm**
- CLI名：**tlvm**
- ソース拡張子：**.tlvm**
- 更新日：2026年10月3日

## 1. 概要

> Tolvemi（トルベミ、省略表記：tlvm）は、有限データ上の純粋・全域・決定的計算のためのDSLです。

Tolvemiは、LLMを含む外部提案器が生成したロジックを、型・停止性・決定性・資源契約の下で検査・評価するための言語として設計されています。

第一の用途は高保証計算カーネル、第二の用途はLLMによる生成・修復の効果を分解して評価する研究基盤です。一般目的言語ではなく、計算の範囲と保証の条件を明示することを重視します。

技術的な説明は、設計書 `LPTL_design_v1.md` に基づきます。本資料は名称と説明の方針をまとめたもので、規範仕様を置き換えません。

## 2. 名称の由来

Tolvemiは、次の二つの概念を着想源とし、響きを整えた造語です。

| 着想源 | 名称に込める意味 |
|---|---|
| total：全域性 | 有効な有限入力に対して、数学的意味論で結果まで到達する計算。 |
| value：値 | 計算の結果を、宣言型に属する有限値として返すこと。 |

正式な頭字語や、二つの英単語をそのまま連結した名称ではありません。各文字や音節に個別の機能名を割り当てる必要もありません。

名称全体として「全域な値計算」を背景に持たせ、独立した一語として使います。

## 3. 省略表記 tlvm

`tlvm` は、`Tolvemi` から母音の `o`、`e`、`i` を除いた子音列に対応します。

```text
Tolvemi → tlvm
```

省略表記は頭字語ではなく、正式名称を短く表す識別子です。公開説明では正式名称を、コマンドやソースファイルでは省略表記を使います。

| 用途 | 使用する表記 |
|---|---|
| 言語名・ブランド名 | Tolvemi |
| 日本語での読み | トルベミ |
| 文書の初出 | Tolvemi（省略表記：tlvm） |
| 文書内の言語名 | Tolvemi |
| CLI実行ファイル名 | tlvm |
| ソース拡張子 | .tlvm |
| パッケージ名・ドメイン名 | 各配布先の利用可能性を確認して別途決定 |

正式名称は先頭のみ大文字の `Tolvemi`、技術的な識別子は小文字の `tlvm` に統一します。省略表記の使用によって、正式名称をTLVMへ変更するものではありません。

## 4. 読みと発音

### 日本語

正式な読みは「トルベミ」です。

```text
ト・ル・ベ・ミ
```

英字7文字、日本語では4拍です。日本語の読みを「トルヴェミ」へ自動的に変更しません。

### 英語の発音案

英語の標準発音候補は、中央の `ve` に主アクセントを置く次の形です。

| 項目 | 発音案 |
|---|---|
| 読みのガイド | tol-VEH-mee |
| 音節 | tol / ve / mi の3音節 |
| 主アクセント | 第2音節 |
| 英国英語寄りのIPA | /tɒlˈvɛmi/ |
| 米国英語寄りのIPA | /tɑlˈvɛmi/ |

これは発音規約としての提案であり、英語話者の初見の読みや記憶試験を実施した結果ではありません。正式な英語発音の確定と利用者試験は、別途管理します。

## 5. 設計思想との関係

### 全域性

設計上の中心契約は、整形式プログラムのentry関数を有効な有限入力に適用すると、数学的意味論で停止し、宣言戻り型に属する一意の有限値を返すことです。

Tolvemiという名称は、この「結果まで到達する値計算」を象徴します。

数学的停止性は、物理ホストでのタイムアウトや資源不足が起こらないことを意味しません。処理系の適合、入力の妥当性、codecの完了、参照予算、ホスト資源などの条件を分離して説明します。

### 純粋性

初期コアでは、可変状態、外部I/O、例外、並行性などを含めません。有限データを受け取り、値を返す計算に範囲を限定します。

純粋性は言語の設計上の性質であり、Tolvemiを含むシステム全体が副作用を持たないという意味ではありません。

### 決定性

同一のプログラム・入力・仕様版に対する数学的結果は一意です。

一意な結果を返すことと、ユーザーの要求に合う正解を返すことは別です。全域性・型安全性・決定性だけで、タスク上の正しさまで保証されるわけではありません。

### 提案と受理の分離

LLMを含む外部提案器は、プログラム候補を生成・修復します。提案器そのものを信頼実行主体にはしません。

静的受理、入力デコード、実行、資源結果、タスク評価を、それぞれの検査責務の下で扱います。

設計思想を短く表す説明文：

> 生成されたロジックを、契約の下で評価する。

これは設計を説明する表現であり、名称の頭字語展開ではありません。

## 6. CLIとファイルの表記

CLI名は `tlvm`、ソース拡張子は `.tlvm` とする命名方針です。

```text
example.tlvm
```

将来のCLI表記の例：

```sh
tlvm check example.tlvm
tlvm run example.tlvm
```

`check`、`run` は表記例です。この資料によってサブコマンド、引数、入出力、実装の存在を確定するものではありません。実際のCLI仕様は、処理系の仕様と実装に従います。

実行ファイル名や拡張子の命名方針と、パッケージレジストリの登録名やドメインの確保は別に扱います。

名称の選択は、商標登録、ドメインや配布名の確保、全先行名称との非類似性、読み書き・記憶試験の合格を意味しません。それらの確認状況は、名称調査・検証の資料で別途管理します。
