# LPTL v1.10 差分仕様：ユーザー定義の型引数（総称の関数・型）

本書は [v1.9 差分仕様](../lptl-v1.9/LPTL_v1.9_delta.md) に対する差分である。汎用言語にするロードマップの 7 段目で、
要素の型だけが違う同じ処理（先頭を取る、重複を除く、二つの列を組にするなど）を、型ごとに書き写さずに一度だけ書けるようにする。

状態：草案。処理系は本書どおりに実装済み。

## 1. 追加するもの

```text
fn f<T, U>(x: T, ys: List<U>) -> R = e        総称の関数（型引数は名前の直後の <...>）
type Box<T> = { value: T, n: Int }            総称のレコード型
type Tree<T> = Leaf | Node(T, Int)            総称の直和型

Box<Int>、Tree<String>                         総称の型の使用（型引数は宣言と同じ数だけ書く）
f(x, ys)                                       呼び出し（型引数は引数の型から推論する）
f<Int, String>(x, ys)                          型引数を明示した呼び出し
Node(x, 1)                                     構築（型引数は中身の型から推論する）
Node<Int>(x, 1)、Leaf<Int>()                   型引数を明示した構築（中身のない構築子は none<T>() と同じく () まで書く）
```

- 型引数の名前は大文字で始まる識別子で、宣言の中（引数の型、戻り型、本体の `list<T>()`・`none<T>()`・`dict<K, V>()`・
  `ok<T, E>(x)`・呼び出しの型引数などの型を書く位置すべて）で使える。型引数は型引数を取らない（`T<Int>` は書けない）。
- 型引数の名前は宣言された型（レコード型・直和型）の名前と重なってはならず、一つの宣言の中で相異なる。
- 型の宣言の型引数は、field（直和型なら variant の中身）のどこかに現れなければならない（型は展開後の構造で決まるので、
  現れない型引数は意味を持たない）。関数の型引数は引数に現れなくてもよい（そのときは呼び出しで明示する）。
- 型は今までどおり構造的で、総称の型は「型引数を入れて展開した構造」の別名である（`Box<Int>` は `Pair<Int, Int>`）。
  再帰型は今までどおり書けない（型はそれを使うより前に宣言する）。
- 例：二つの型で同じ補助関数を使う。

```text
fn first<T>(xs: List<T>) -> Option<T> = match uncons(xs) { some(p) => some(fst(p)), none => none<T>() }
fn solve(xs: List<Int>) -> Pair<Option<Int>, Option<String>> = pair(first(xs), first(list<String>("a", "b")))
entry solve
```

### 1a. 型検査

- 総称の関数の本体は一度だけ、型引数を**不透明な型**として検査する。型 `T` の値に使えるのは、どの型でも型が付く操作だけ：
  `eq`（全ての値は構造的等価性を持つ）、`pair`・`fst`・`snd`、`some`・`none<T>()`、`list<T>(...)`・`cons`・`concat`・`reverse`・
  `length`・`uncons`・`contains`、`fold`・`map` など・`loop`、辞書の鍵や値、ほかの関数への受け渡し。`add`・`lt`・`sort`・
  `to_string` などの特定の型の操作に `T` の値を渡すと `E-TYPE-ARG`（expected `Int`、found `T`。修復ヒントで、その型の引数を
  取るか呼び出し側で行うよう示す）。使われない総称の関数も本体は検査する。
- 呼び出しの型引数は、明示していればそれを使い、なければ**引数の型との一階の照合**で決める：引数を左から順に、宣言した
  引数の型の中の型引数を実際の引数の型の対応する部分に束縛する。同じ型引数に違う型が当たれば `E-TYPE-GENERIC-MISMATCH`
  （expected に先の型、found に後の型）、形が合わなければ `E-TYPE-ARG`。束縛されない型引数（戻り型だけに現れるなど）が
  残れば `E-TYPE-GENERIC-INFER`（修復ヒントで `f<Int>(...)` の形を示す）。戻り値の型は推論した型引数を入れたもの。
  呼び出しの外の文脈（期待される戻り型など）からは推論しない（`none<T>()` に型引数を書くのと同じ方針）。
- 明示した型引数の数が違えば `E-TYPE-GENERIC-ARITY`。総称でない関数に型引数を書いても同じ。
- 総称の直和型の構築 `Node(x, 1)` は、型引数を推論する総称の関数の呼び出しと同じ規則で検査する（中身から決まらない型引数は
  明示する：`type Either<A, B> = Left(A) | Right(B)` の `Left(1)` は `Left<Int, String>(1)` と書く）。中身のない構築子
  （`Leaf`）は推論の手がかりがないので、型引数を必ず書く（`Leaf<Int>()`）。pattern は今までどおり `Leaf`、`Node(x, n)`。
- `match` の対象・field の参照の対象が総称の型なら、対象の型と展開後の型を照合して型引数を決め、束縛・field の型に入れる。
- entry の関数は総称にできない（`E-ENTRY-GENERIC`。修復ヒントで具体的な型の包み関数を示す）。

### 1b. 入出力

entry の入力型・出力型に、型引数を入れた総称の型（`Box<Int>`、`Opt<String>`）を使える。plain JSON・値 JSON は展開後の
構造と同じで、レコード型・直和型の形は v1.1・v1.4 のとおり。`tlvm check` の型の表示は `Opt<String>` のように型引数を付ける
（展開後の型から型引数を復元する）。`tlvm exec` の入力型は v1.3 の 3 形のまま。

## 2. 検証との関係

検証済みの中核は変えない。接着部分（`crates/tlvm/src/generics.rs`。総称の型の展開は `records.rs`・`sums.rs`）が、型検査の後に
**単相化**してから検証済み部品に渡す。

1. 型引数の解決（phase name）：宣言の型引数を検査し、型の位置の型引数の名前を型引数の node にする。
2. 展開：総称のレコード型・直和型の使用 `Box<Int>` は、宣言の展開後の型の型引数を置き換えたもの。型引数を推論する構築
   `Node(x, 1)` は、展開で作る総称の関数（`fn node_new<T>(a1: T, a2: Int) -> Tree<T> = err<Unit, Pair<T, Int>>(pair(a1, a2))`
   のような関数。名前はプログラム中のどの名前とも重ならない）の呼び出しになる。型引数を書いた構築は、その型で直接展開する。
3. 型検査（§1a）：総称の関数の呼び出しごとに型引数を記録する。
4. 多相再帰の検査：呼び出しのたびに型引数が大きくなる再帰（`rec fn g<T>(...)` の本体から `g<List<T>>` を呼ぶなど。相互再帰を
   通るものも）は、具体化が無限に続くので `E-TYPE-GENERIC-INFINITE` で拒否する。総称の関数 f の型引数 P から、f の本体の
   呼び出し `g<..., A_j, ...>` の g の j 番目の型引数へ、A_j が P を含めば辺を引き（A_j が P そのものなら重み 0、P を真に
   含めば重み 1）、重み 1 の辺が閉路に乗れば拒否する。型引数が大きくなっても具体的な型で閉じる呼び出しは許す。
5. 単相化：総称でない関数から出発し、使われた（関数、具体的な型引数の組）ごとに総称の関数を複製する。複製の名前は
   `first_g1` などの、プログラム中のどの名前とも重ならないもの。本体の型引数を具体的な型に置き換え、総称の関数の呼び出しを
   複製の呼び出しにする。`rec` の印は複製に移る。使われない総称の関数はコードにならない（`rec fn` でも停止の保証を失わない）。
   総称の関数の宣言そのものは除く。
6. 上限：複製は 256 個まで、型引数一つの大きさは型の node 256 個まで（`E-LIMIT-STATIC-GENERIC-INSTANCES`、phase
   semantic-limits）。再帰がなくても型引数が関数ごとに倍になる呼び出しの鎖などはこれで止める。
7. 単相化したプログラムをもう一度型検査し、以降は今までどおり（`map` などの書き換え、レコード型・直和型の lower）で検証済み
   部品に渡す。

- 停止性・型安全性・決定性（v1 §11.2）は単相化・書き換え後のプログラムについて成り立つ。単相化は有限で終わる（多相再帰の
  拒否と上限による）。
- `rec fn`・`loop`・`map` など・辞書・レコード・直和型・`match` と組み合わせられる（型引数を辞書の鍵・値、`loop` の状態、
  レコードの field、直和型の中身にしてよい）。
- AST transport（この処理系の拡張）：関数に `"type_params":["T", ...]`（総称の関数にだけ書く）、型 `{"tag":"param","name":"T"}`、
  呼び出しに `"type_args":[型, ...]`（明示したときだけ）。レコード型・直和型の宣言は今までどおり transport にないので、`tlvm ast`
  は展開したもの（構築子のために作った総称の関数を含む）を出す。
- 正準整形：`fn f<T, U>(...)`、`type Box<T> = ...`、`Box<Int>`、`f<Int>(x)`、`Leaf<Int>()`。総称の構文を含むプログラムは
  検証済み formatter の対象外で、`tlvm fmt` は診断用 formatter の出力を出す。

## 3. 診断

| コード | phase | 意味 |
|---|---|---|
| `E-TYPE-GENERIC-UNKNOWN-PARAM` | name | 宣言されていない型引数（総称の宣言の中の未知の型名か、総称でない宣言の `T` のような名前で、近い名前の型も無いもの）。修復ヒントで `<T>`・`<T, U>` の宣言を示す |
| `E-TYPE-GENERIC-ARITY` | name / typecheck | 型・呼び出し・構築の型引数の数が宣言と違う（総称でないものに型引数を書いた、型引数に型引数を書いたも含む） |
| `E-TYPE-GENERIC-DUPLICATE-PARAM` | name | 一つの宣言に同じ名前の型引数が二つ |
| `E-TYPE-GENERIC-PARAM-CONFLICT` | name | 型引数の名前が宣言された型の名前と同じ |
| `E-TYPE-GENERIC-UNUSED-PARAM` | name | 型の宣言の型引数が field・variant のどこにも現れない |
| `E-TYPE-GENERIC-INFER` | typecheck（中身のない構築子は name） | 型引数を推論できない。修復ヒントで明示の形（`mk<T>(...)`、`Leaf<Int>()`）を示す |
| `E-TYPE-GENERIC-MISMATCH` | typecheck | 同じ型引数に、引数によって違う型が当たった（expected／found） |
| `E-TYPE-GENERIC-INFINITE` | typecheck | 多相再帰（§2 の 4） |
| `E-ENTRY-GENERIC` | entry | entry の関数が総称 |
| `E-LIMIT-STATIC-GENERIC-INSTANCES` | semantic-limits | 単相化の上限（§2 の 6） |

- 総称でない宣言で、宣言された型に近い名前（`R` に対する `P` など）は今までどおり `E-RECORD-UNKNOWN-TYPE` で、名前が型引数らしい
  （大文字一文字か、大文字一文字と数字）ときは修復ヒントに型引数の宣言の形も添える。
- 宣言の型引数が大文字で始まらなければ `E-PARSE-EXPECTED-IDENT`、`Leaf<Int>`・`f<Int>` の後に `(` がなければ
  `E-PARSE-EXPECTED-TOKEN`（修復ヒントで `()` を示す）。
