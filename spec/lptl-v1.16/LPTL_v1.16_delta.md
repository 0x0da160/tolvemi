# LPTL v1.16 差分仕様：パッケージ（ローカルの依存）

本書は [v1.11 差分仕様](../lptl-v1.11/LPTL_v1.11_delta.md)（ほかの source ファイルの import）に対する差分である。
v1.0.0 の仕様凍結の前に決める「パッケージ管理」の最小の形を定める。import の文字列に `@名前/…` の形を加え、
マニフェスト `tlvm.json` で依存を宣言する。型・式・評価・検証済みの核は変えない。

状態：草案。処理系は本書どおりに実装する（`crates/tlvm/src/packages.rs`、`crates/tlvm/src/imports.rs`）。

## 0. 決めたこと

- **依存はローカルのディレクトリだけ**。レジストリからの取得、版の範囲指定、版の解決、ロックファイルは含めない。
  外から取ったコードを検査の前に信頼させず、ネットワークに依らない。取得と版の解決は v1.0.0 の対象外で、後の別の版で扱う。
- **依存の場所は根のディレクトリの内側**。`..` で根のディレクトリより上へは出られない（v1.11 の規則と同じ）。
- **名前空間は平坦のまま**（v1.11）。依存の定義も根の定義と同じ一つの名前空間を共有し、同じ名前は `E-IMPORT-CONFLICT`。
- **版は完全一致の固定だけ**。宣言に `"version"` を書けば、依存のマニフェストの版と等しくなければ拒否する。

## 1. マニフェスト `tlvm.json`

パッケージは、マニフェスト `tlvm.json` を置いたディレクトリである。マニフェストは JSON のオブジェクトで、
次の鍵だけを持つ（ほかの鍵は `E-PKG-MANIFEST`）。

| 鍵 | 型 | 意味 |
|---|---|---|
| `name` | 文字列 | パッケージの名前。依存として使われるパッケージでは必須（§3） |
| `version` | 文字列 | 版。`MAJOR.MINOR.PATCH`（十進の数字の三つ組）。省けば版はない |
| `dependencies` | オブジェクト | 依存。鍵は依存の名前、値は下の表のオブジェクト |

依存の値のオブジェクト：`path`（文字列、必須）と `version`（文字列、任意。版の固定）。ほかの鍵は `E-PKG-MANIFEST`。

- パッケージの名前と依存の名前は `[a-z][a-z0-9_]*`（64 bytes まで）。
- マニフェストは 64 KiB まで、JSON の入れ子は 4 段まで（厳格な JSON の規則。重複する鍵は拒否）。
- 例：

```json
{
  "name": "app",
  "version": "1.0.0",
  "dependencies": {
    "stats": { "path": "deps/stats", "version": "0.2.0" },
    "text": { "path": "vendor/text" }
  }
}
```

## 2. ファイルの属するパッケージ

- ファイルは、そのファイルのディレクトリから上へ順にたどって**最初に見つかる** `tlvm.json` のディレクトリのパッケージに属する。
  根のディレクトリより上へはたどらない。`tlvm.json` が一つもなければ、そのファイルはパッケージに属さない。
- 属するパッケージは、`@` で始まる import が使う依存の表を決める。ファイルの場所だけで決まり、import の順には依らない。
- `@` のない import（v1.11 の相対パス）は今までどおりで、属するパッケージを変えない。ほかのパッケージのディレクトリの
  中のファイルを相対パスで import してもよい（カプセル化は v1.16 にない。§8）。

## 3. 依存の宣言と読み込み

- 依存の `path` は、宣言したパッケージのディレクトリからの相対パス（`/` 区切り。`.` と `..` を含んでよい）。
  正規化して、根のディレクトリの内側にあり、根でも宣言したパッケージ自身のディレクトリでもないこと（`E-PKG-PATH`）。
  絶対パス、空の要素（`a//b`、末尾の `/`）、`\`・`:`・制御文字を含むものも `E-PKG-PATH`。
- 依存のマニフェストは、`@名前/…` の import で使われたときに読む（遅延）。宣言しただけで使わない依存は読まない。
  読めないとき（そのディレクトリに `tlvm.json` がない）は `E-PKG-NOT-FOUND`。
- 読んだマニフェストの `name` は、宣言した依存の名前と等しいこと（`E-PKG-NAME`）。
- 宣言に `version` があれば、読んだマニフェストの `version` と完全一致すること（`E-PKG-VERSION`。依存に版がなければ不一致）。
- 依存のマニフェストの依存は、その依存のマニフェストに書かれたとおりに、使われたときに同じ規則で読む。

## 4. `@` の import

```text
import "@stats/summary.tlvm"
```

- `@名前/パス` の形。`名前` は、import するファイルのパッケージの依存の名前。宣言していなければ `E-PKG-UNKNOWN`
  （`tlvm.json` がないパッケージも同じ）。
- `パス` は依存のディレクトリからの相対パスで、v1.11 と同じ字句の規則（`/` 区切り、`.tlvm` で終わる、空の要素なし）。
  依存のディレクトリより上へ出る（`..` で）ものは `E-IMPORT-PATH`。
- `@` だけ、`@名前` だけ（`/` がない）、名前が規則に合わないものは `E-IMPORT-PATH`。
- 循環（依存をまたぐものを含む）は `E-IMPORT-CYCLE`、ファイルがなければ `E-IMPORT-NOT-FOUND`、名前の衝突は
  `E-IMPORT-CONFLICT`（いずれも v1.11 と同じ）。
- `@` で読んだファイルは、ほかの import と同じく一度だけ読む（菱形の import でも一度）。

## 5. 診断（新しく加えたもの）

段階は import。

| コード | 意味 |
|---|---|
| `E-PKG-MANIFEST` | `tlvm.json` が JSON でない、大きすぎる、鍵や値の形が違う（未知の鍵、名前・版の形） |
| `E-PKG-PATH` | 依存の `path` が不正（§3） |
| `E-PKG-NOT-FOUND` | 依存のディレクトリに `tlvm.json` がない |
| `E-PKG-NAME` | 依存のマニフェストの `name` が宣言した名前と違う、または無い |
| `E-PKG-VERSION` | 版の固定と依存の版が違う、または依存に版がない |
| `E-PKG-UNKNOWN` | `@名前/…` の名前が、そのファイルのパッケージの依存でない |

`@` の書き方の誤りは既存の `E-IMPORT-PATH`。ほかは v1.11 の診断をそのまま使う。

## 6. 検証との関係

- 検証済みの核（`verus/`）は変えない。解決は接着部分（`crates/tlvm/src/packages.rs`、`crates/tlvm/src/imports.rs`）で、
  結果はつないだ一つの source（v1.11 と同じ）。検証済みの部品はそれを検査・実行する。
- 依存の取り違え（別のディレクトリを読むこと）は検証の外にある。ただし、読んだ依存の中身は、検査・実行される
  つないだ source そのものになる。

## 7. 互換

- `@` を使わず、`tlvm.json` も使わないプログラムは、v1.11 と同じに動く。
- `tlvm.json` があっても、`@` の import で使われなければ読まない（§3）。したがって、既存のプログラムは影響を受けない。
- 変わるのは、import の文字列の先頭が `@` のときだけ。v1.11 では `@` で始まるパスは `E-IMPORT-PATH` だった。

## 8. 次の課題（候補）

- レジストリからの取得、版の範囲指定と解決、ロックファイル（取得するようになってから）。
- パッケージ単位のカプセル化（依存の中のファイルを相対パスで import させない）と、名前の接頭辞。
- 速度の目標（v1.0.0 の前に別に決める）。
