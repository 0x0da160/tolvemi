# LPTL v1.3 差分仕様：入出力ランタイム

本書は [v1.2 差分仕様](../lptl-v1.2/LPTL_v1.2_delta.md) に対する差分である。言語（構文・型・評価）は変えない。
プログラムをコマンドとして動かす実行の仕組み `tlvm exec` を加える。

状態：草案。処理系は本書どおりに実装済み。

## 1. 方針

言語の中核は純粋なまま保つ。プログラムは「入力のテキストから出力のテキストへの関数」で、標準入力・引数を
読み、標準出力に書くのはランタイムである。したがって停止性・型安全性・決定性（v1 §11.2）はそのまま成り立つ。

## 2. `tlvm exec FILE [ARGS...]`

entry の入力型で、ランタイムが渡すものが決まる。

| entry の入力型 | 渡すもの |
|---|---|
| `String` | 標準入力の全文 |
| `List<String>` | コマンドライン引数（FILE より後ろの語。`--` で始まる語もそのまま渡す） |
| `Pair<List<String>, String>` | 引数と標準入力の全文 |

- 出力型が `String` なら、その文字列をそのまま標準出力に書く（改行は足さない）。それ以外の出力型は plain JSON を
  一行で書く。
- 終了コード：0 は完了。1 は検査で拒否（診断は従来どおり標準エラーへ）か、標準入力が UTF-8 でない
  （`InputBoundaryFailure`）。2 は資源の打ち切り（`ResourceExhausted`、`HostAborted`）。3 は処理系の不具合
  （`InternalFault`）。64 は entry の入力型が上の表にない（`UnsupportedEntry`）。
- 資源：`execution-exec-1`（steps 10 億、割当 node 6400 万、出力 256 MiB）。入力の大きさには上限を置かず、
  割当 node が実質の上限になる。

## 3. 検証との関係

- 検証済み部品（`verus/src/io.rs`）：テキストから値への変換 `text_value`（`view_val == Val::List(chars(s))`）、
  引数の列 `args_value`、値からテキストへの変換 `text_codes`。実行は検証済みの `pipeline::run_checked`
  （entry の入力型の検査、spec の唯一の結果、Fault にならないこと）を使う。JSON を経由しないので、大きなテキストも
  速く読める（2 MB の標準入力で 2 秒程度）。
- 検証されていない接着部分（`crates/tlvm/src/runtime.rs`、`main.rs` の exec）：入力の形の選択、標準入力の
  UTF-8 検査、文字の番号から文字への変換、結果を終了コードに写すこと。

## 4. まだないもの

終了コードをプログラムが選ぶこと、標準エラーへの出力、ファイルの読み書きは、直和型（`Result`）が入った後に足す
（汎用言語化のロードマップの順）。
