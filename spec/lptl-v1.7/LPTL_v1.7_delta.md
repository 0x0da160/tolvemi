# LPTL v1.7 差分仕様：印をつけた関数の再帰 `rec fn`

本書は [v1.6 差分仕様](../lptl-v1.6/LPTL_v1.6_delta.md) に対する差分である。汎用言語にするロードマップの 5 段目の後半で、
利用者の決定「既定で保証」（2026-10-12）に従い、`rec` の印をつけた関数だけ上限なしの再帰を許す。

状態：草案。処理系は本書どおりに実装済み。

## 1. 追加するもの

```text
rec fn f(x: T, ...) -> R = e
```

- `rec` を付けた関数は、どの関数からでも呼べる（自分自身からも）。循環する呼出しは、循環のどこかに `rec` 関数が 1 つあれば許す（相互再帰も可）。
- 印のない関数どうしの呼出しは今までどおり循環してはならない（`E-CYCLE-CALL`。修復ヒントで `rec` を勧める）。
  呼出しグラフから「`rec` 関数へ入る辺」を除いたものが DAG であればよい。
- `rec` は文脈キーワード：最上位で直後が `fn` のときだけ印。変数名やフィールド名としては使える。`entry` には付けられない。
- 例：`rec fn gcd(a: Int, b: Int) -> Int = match mod(a, b) { some(r) => if(eq(r, 0), b, gcd(b, r)), none => a }`

## 2. 保証の範囲

| | `rec` 関数のないプログラム | `rec` 関数のあるプログラム |
|---|---|---|
| 停止する（資源上限の前に値が出る） | 証明済み（従来どおり） | 保証しない |
| 実行時に型の不一致で止まらない | 証明済み | 保証しない |
| 返した値は宣言した型を持つ | 証明済み | 証明済み（新しい定理 `sound`） |
| 返した値は spec の評価の唯一の結果 | 証明済み | 証明済み |
| 実行は資源上限（step 数・深さ・割当）で必ず止まる | 実装で保証 | 実装で保証 |

止まらない再帰は、従来の資源上限の診断（step 数の上限など）で終わる。`tlvm check` は `rec` 関数を含むプログラムを
「停止は保証されない」と報告する。

## 3. 検証済みの中核の変更

- `Prog` に `rec: Seq<bool>`（関数ごとの印）を足す。呼出しの型付け条件を
  「`rank[g] < r`」から「`rank[g] < r` または `rec[g]`」に広げる。`wf` は `rec.len() == funcs.len()` も要求する。
- 停止性の定理 `total` に「印のある関数がない」（`no_rec(p)`）を前提として足す。
- 新しい定理 `sound`：整形式のプログラムで、型の付いた式がある燃料で値 v に評価されたなら、v はその型を持つ。
  （燃料についての帰納法。停止性を使わない。）
- `run_checked` などの事後条件：返した値の型と一意性はすべての整形式プログラムで、`!is_fault` は `no_rec(p)` のときに保証。
- 印 `rec` の列は、ランクと同じく未検証の接着部分が作って `compile_source` に渡す。検証済みの構文解析器は `rec` を知らない
  （接着部分が取り除く）。接着部分が印を落とした場合は循環として拒否されるので安全側。余計に付けた場合は、停止の保証を
  主張しなくなるだけ（型と一意性の保証は残る）。

## 4. 診断

| コード | phase | 意味 |
|---|---|---|
| `E-CYCLE-CALL` | callgraph | 印のない関数を含む循環。修復ヒント：循環にある関数に `rec` を付ける |
| `E-PARSE-REC-ENTRY` | parse | `rec entry` は書けない |
