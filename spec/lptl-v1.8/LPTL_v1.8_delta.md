# LPTL v1.8 差分仕様：整数の割り算 `div`

本書は [v1.7 差分仕様](../lptl-v1.7/LPTL_v1.7_delta.md) に対する差分である。汎用言語にするロードマップの 6 段目の最初で、
これまで無かった整数の割り算を足す（v1.6 の問題 93 では、半分にするために 2 の冪を積み上げる回り道が要った）。

状態：草案。処理系は本書どおりに実装済み。

## 1. 追加するもの

```text
div(a, b)    Int, Int -> Option<Int>
```

- `b > 0` のとき `some(q)`。q は床除算の商で、`mod` と組にして `a = q * b + r`、`0 <= r < b`（`r` は `mod(a, b)` の値）。
  例：`div(7, 2) = some(3)`、`div(-7, 2) = some(-4)`（`mod(-7, 2) = some(1)`）。
- `b <= 0` のとき `none<Int>()`（`mod` と同じ扱い。負の除数は使わない）。
- `div` は `mod` と同じ扱いの組み込み名（文脈キーワード。変数名などには使え、関数名には使えない）。

## 2. 検証済みの中核の変更

組み込み関数として検証済みの中核に入れる（`mod` と同じ経路）。

- spec：`Builtin::Div`、型 `Int, Int -> Option<Int>`、評価は `y > 0` なら `some(x / y)`（Verus の `int` の `/`。正の除数では床除算）、
  それ以外は `none`。`apply_sound` に場合を足す。
- exec：信頼する多倍長整数に `div_pos`（num-bigint の `div_floor`。事後条件 `r@ == self@ / o@`）を足す。これは
  `mod_pos` と同じ種類の信頼仮定で、trust-boundary.toml の `[bigint]` に記録する。
- 構文：キーワード表・字句解析・構文解析・整形と、それらの証明に `div` を足す。

## 2a. `loop` の手間の修正

v1.6 の `loop` の書き換え（接着部分 `hof.rs`）は `fold(range(0, max), ...)` だったので、早く止まっても手間が max に
比例した。問題 95（n を b 進の桁に分ける）で、上限を `add(n, 1)`（n は約 10^12）にした回答が資源上限で失敗して見つかった。
長さ 16 のリストを辿る fold を 16 段入れ子にする書き換えに改め、手間を実際に評価した回数に比例する分と定数の上乗せにした。
意味（`some`／`none` と本体の評価回数）は変わらない。詳細は [v1.6 差分仕様 §2](../lptl-v1.6/LPTL_v1.6_delta.md)。
検証済みの中核は変えない。

## 3. LLM での確認

この機能を使う問題 1 つを Haiku（effort low）で 1 回解かせる（結果は §4 に書く）。

## 4. 結果

- 検証：626 件、エラー 0（`div_pos` は信頼する多倍長整数の演算なので件数は増えない）。`cargo test --release --locked` は 126 件すべて成功。
- 実行 `20261013T052717Z-claude-cli`（Haiku・effort low・1 回）：95-base_digits は不正解（隠しテスト 7/30）。回答は `div`・`mod`・`loop`
  を正しく使っていたが、`loop` の上限を `add(n, 1)` にしたため、当時の展開（上限ぶんの `range` を作る）で資源の上限を超えた。
- §2a の修正後、同じ回答は隠しテスト 30/30 で通る（Haiku は再実行していない。回答をそのまま検査器で実行して確認）。
